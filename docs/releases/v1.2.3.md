Release of the recipe: DeepSeek-V4.1-Flash-1017 (EXL3 2.9 bpw, Engram from local NVMe) on two DGX Sparks at TP=2 over CX-7, with sparkrun.

Image: `ghcr.io/ursuciprian/ds41-tensorfold:v1.2.3`, digest `@@DIGEST_V123@@` (engine commit `1e23063`, v1.2.2 plus two decode options that are off unless set; the gated build with image labels added, same layers).

Drafter: D1, unchanged (`ursuciprian/DeepSeek-V4.1-Flash-1017-DSpark-D1` @ `ca1a99a8f07e4ec45addc71d77f5fc73ee3b1c5f`).

What is in it:
- `TF_DSV41_X3LD_MTILE_FAST: '1'` in the recipe. In decode windows above 16 rows (C4 and C8 with drafts) the routed-expert kernel now launches the two member tiles of a work item next to each other, so the second tile reads expert weights the first one just pulled into L2. Same work items and same arithmetic: the output is bit-identical, checked bit for bit by a GPU test on the real layer shapes.
- `TF_DSV41_ROUTER_TILE4`, a second decode option in the image, did not pass my kernel step. It is off unless set; the recipe does not set it.

Measured on my pair, v1.2.3 settings against v1.2.2 settings in alternating boots (A B B A) on 2026-11-15, one image, the new line the only difference, under a keep rule written before the first boot:
- decode, aggregate C8, mean of 2 boots: code 169.0 to 172.6 tok/s (+2.1%), thinking-75 139.8 to 143.2 (+2.4%), prose 123.6 to 126.7 (+2.6%); code C4 +1.3%. C1 cells within noise (+0.1% to +0.6%). No cell worse.
- agentic C8, 24 prompts per bucket: no bucket worse, replies text-identical on 144 of 144. The 32K bucket was faster in both pairs (-7.8% and -6.9% wall), but the first v1.2.2 boot was slower than the other three on every bucket and my rule only tests for worse, so I do not claim an agentic gain.
- eight 124K-token prompts at once: 470 and 468 s against 474 and 467 s, 8 of 8 answered on every boot, no refusal.
- prefill on real text and short-prompt time to first token: no cell worse; I do not claim a prefill change.
- a first run of the same A/B on 2026-11-13 missed my keep rule on one cell (short-prompt time to first token on `/v1/completions`, 0.199 s against 0.196 and 0.198 s, +1.02% at a 1.02% noise floor) and nothing shipped then. This run is the one confirmatory rerun I allowed myself, with the rule text unchanged. Both runs are in BENCHMARKS.md.

Quality, on the release build with this recipe and D1 on 2026-11-15 (one boot, healthy after 296 s): the full gate passed (hardmode 93, bar 88), exactness 32 of 32 at C1 and C8, 27 of 27 greedy replies against v1.0.1, and needle retrieval exact on 20 of 20 at 247K in the gate and on two more runs at 241K. Engine tests for the changed code: 90 passed on the GPU and host, 23 under the Triton interpreter; two mutants of the new launch order were caught. Not rerun on this image: the full v1.2.2 engine suite and the thinking switch smoke (the request code is the same as in v1.2.2).

Upgrading from v1.2.2: pull the new image and add `TF_DSV41_X3LD_MTILE_FAST: '1'` to the recipe's `env`, or take the new recipe. Every other setting stays as in v1.2.2.
